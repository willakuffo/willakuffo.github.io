On the Design of Terminal Ingredients for Model Predictive Contouring Control

MSc thesis, Institute for Dynamic Systems and Control, ETH Zürich, 2024
Supervisors: Prof. Dr. Melanie Zeilinger, Dr. Andrea Carron

A finite-horizon MPC leaves an optimality gap: it cannot see past the end of its horizon. A terminal cost is meant to fill that gap, but for a racecar on a complex track it is hard to design by hand. This work learns it instead, using the critic of an actor-critic reinforcement learning agent as the terminal cost-to-go of a model predictive contouring controller (MPCC).

Approach

  • Controller. MPCC minimises contouring error while maximising progress along the track, so a racing line emerges implicitly. Implemented in acados, with a Pacejka tyre model in curvilinear coordinates, which makes the track-limit constraints linear in lateral deviation.
  • Learned terminal cost. An actor-critic agent is trained offline in the same racing environment. Its value function, a neural network, is plugged into the optimal control problem through L4CasADi as the terminal cost V(xt+N).
  • Simulation. A custom simulator integrates the Pacejka dynamics with RK4 at a 0.03 s sampling time.
  • Warm starting. On straights, guessed inputs are propagated through the dynamics. In hard-to-guess regions such as the chicane, the trained RL policy (the actor) supplies the initial guess.

Results

Two cars start from the same state with the same MPCC; only one has the learned terminal cost.

Performance at N = 20
MPCC + learned terminal costMPCC only
Lap time4.63 s4.78 s
Average velocity3.78 m/s3.65 m/s

A 0.15 s gain per lap looks small, but it compounds: over many laps the car with the learned terminal cost pulls clearly ahead.

Compute

Evaluating the neural-network terminal cost adds solver time at both horizons, but every solve stays below the 0.03 s sampling time. Without a terminal cost, the N = 20 controller was, counter-intuitively, slower than N = 30: being short-sighted, it often failed to meet the KKT tolerances within the 100-iteration SQP limit.

Limitations and next steps

  • No invariant terminal set was designed, so recursive feasibility is not guaranteed; closed-loop behaviour relies on cost-weight tuning.
  • Balancing the scales of contouring, progress and terminal-cost terms was essential for numerical conditioning.
  • Ongoing: context-conditioned terminal value functions, including a multi-agent variant conditioned on neighbouring agents.
